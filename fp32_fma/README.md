# FP32 FMA

IEEE 754 binary32の三入力に対して`a * b + c`を計算する、
合成可能なSystemVerilog組合せ回路です。乗算結果をbinary32へ丸めずに加算し、
最後に一度だけ、入力信号で指定したモードへ丸めます。入出力subnormalを扱います。

- トップモジュール: `FP32FMA`
- インターフェース: clockなしの32-bit三入力・一出力、3-bit丸めモード入力
- 非正規化数: 入力・出力とも対応、FTZなし
- 精度: 指定モードで正しい一回丸め、途中丸めなし
- 丸めモード: RNE・RTZ・RDN・RUP・RMMを実行時選択

## ファイル構成

```text
fp32_fma/
├── fp32_fma.sv
├── README.md
├── Makefile
└── test/
    ├── reference.hpp
    └── test.cpp
```

`fp32_fma.sv`だけが合成対象です。`test/reference.hpp`はMPFRによる独立参照、
`test/test.cpp`は特殊値・境界・固定seed乱数の検査に使います。
近似係数テーブルはないため、定数生成・定数照合は対象外です。

## インターフェース

```systemverilog
module FP32FMA (
    input  wire [31:0] a,
    input  wire [31:0] b,
    input  wire [31:0] c,
    input  wire [2:0] rounding_mode,
    output wire [31:0] result
);
```

`a`、`b`、`c`、`result`はIEEE 754 binary32のbit patternです。
clock、reset、valid、ready、例外flag、NaN payload保持、演算を切り替えるopcodeはありません。
`rounding_mode`の符号化は後述の数値仕様を参照してください。

```systemverilog
FP32FMA u_fma (
    .a(a),
    .b(b),
    .c(c),
    .rounding_mode(rounding_mode),
    .result(result)
);
```

`a`、`b`、`c`、`rounding_mode`の変化が組合せ遅延を経て`result`へ反映されます。
クロック境界での入力保持・出力取り込みが必要な場合は、利用側でレジスタを設けてください。

## 合成時パラメータ

合成時パラメータはありません。FP32の積和、入出力subnormal対応、組合せ回路で固定です。
入出力幅・精度の変更や、FTZへの切替は設定できません。丸めモードは実行時入力で指定します。

## 数値仕様

数値仕様は、無限精度の`a * b + c`を指定モードで一度だけbinary32へ丸めた結果とのbit一致です。
乗算途中には丸めを入れません。NaNはcanonical化し、例外フラグは出力しません。
検証済みの範囲は後述の「検証済み精度」に示します。

| 入力または条件 | 出力 |
|---|---|
| 入力NaN、`0 * Inf`、無限積と逆符号の無限加数 | canonical quiet NaN `0x7fc00000` |
| 上記以外の無限入力 | 積または加数の符号に従うInf |
| 有限値のoverflow | 丸めモードと符号に応じてInfまたは最大有限値。相殺は丸め前に扱う |
| 逆符号の厳密な相殺 | RDNだけ`-0`、他は`+0` |
| 同符号zero同士の和 | 同じ符号のzero |
| 入力subnormal | zeroへ置換せず計算する |
| 結果がunderflow領域 | 指定モードで丸めたsubnormalまたはzero。最小normalへの繰り上がりも扱う |
| 非zeroの結果がzeroへ丸まる | 結果の符号を保持したzero |

### 丸めモード

| `rounding_mode` | モード | 丸め方向 | 有限値のoverflow時の出力 |
|---|---|---|---|
| `3'b000` | RNE | 最近接、同点は偶数 | 符号付きInf |
| `3'b001` | RTZ | zero方向 | 符号付き最大有限値 |
| `3'b010` | RDN | 負の無限大方向 | 正は最大有限値、負は`-Inf` |
| `3'b011` | RUP | 正の無限大方向 | 正は`+Inf`、負は負の最大有限値 |
| `3'b100` | RMM | 最近接、同点は絶対値が大きい側 | 符号付きInf |

`101`・`110`・`111`は未対応の符号化として`0x7fc00000`を返します。
CSR等から動的にモードを選ぶ機能は持たず、利用側で上記の値へ解決して入力します。
固定モードで使う場合もこの入力を定数へ接続できます。

## テスト

リポジトリ直下から次を実行します。

```sh
make lint-fp32_fma
make test-fp32_fma
make -C fp32_fma stress
```

`fp32_fma/`内では、それぞれ`make lint`、`make test`、`make stress`です。
リポジトリ直下の一括`make lint`・`make test`・`make clean`にも含まれます。
定数生成は不要で、三入力全数検査には対応しないため、`make constants-check`・`make exhaustive`は対象外です。
`stress`は通常テストとは分けて実行します。

`make test`の乱数組数は次のように変更できます。各組を全5モードで検査します。

```sh
make test-fp32_fma RANDOM_CYCLES=1000000
```

MPFR 640 bitで積和を評価し、RNE・RTZ・RDN・RUPはMPFRの対応モードで
binary32へ丸めた独立参照とbit比較します。
RMMはRNE結果を基準に、厳密な値が隣接するbinary32値の中点に一致する場合だけ
絶対値の大きい側を選びます。参照はRTLのGRS判定を共有しません。
640 bitは有限binary32積和の指数範囲を覆い、参照の積和を正確に保持する幅です。
NaNだけは仕様に従ってcanonical化します。

特殊値の直積、指数差・bypass境界、相殺、tie、丸めcarry、最小subnormal、最小normal、
overflowと相殺の組合せ、固定seed乱数を全5モードで検査します。
同じ三入力でモードだけを変える検査と、未対応符号化の検査も行います。
各入力の組合せ出力を直ちに照合します。
これらのsimulationは三入力全`2^96`組合せの全数検査や形式証明ではありません。
`stress`は乱数を増やす追加標本検査です。別途実施した[形式等価性検証](#形式等価性検証)は後述します。

## 検証済み精度

### 数値検査

2026-10-05に、仮数出力選択を統合した現行RTLを再ビルドし、次を再確認しました。
件数は全5モードの合計で、予約符号化は別に示します。

| 指標 | 結果 |
|---|---:|
| 通常検査 | 2,766,100件 |
| 通常検査のbit不一致 | 0 |
| stress検査 | 58,900,015件 |
| stress検査のbit不一致 | 0 |
| 各検査の予約符号化 | 52,728件 |
| 予約符号化のcanonical NaN不一致 | 0 |
| lint | PASS |

1モードあたり通常553,220組、stress 11,780,003組の三入力を検査しています。
stressは全有限乗数指数field組の境界検査と乱数500万組を含みます。
「全有限指数field組」は乗数二入力の指数0～254の組であり、全仮数・全加数の列挙ではありません。
全有限指数と仮数内23位置で、相殺後の2の冪とその両隣を作る指向検査も含みます。
乱数seedは`0xf32f0a01`、NaNはcanonical値で照合します。
これらはVerilated RTLモデルによる標本・境界検査です。以下の形式等価性検証とは区別します。

### 形式等価性検証

2026-10-06、Berkeley HardFloat Release 1（RISCV specialization）を比較対象とする形式等価性検証により、
三入力の全`2^96`通りとRNE・RTZ・RDN・RUP・RMMの全5丸めモードの全組合せで、32-bit結果の一致を証明しました。
入出力subnormal、NaN・Inf・符号付きzero、overflow／underflowを含みます。

NaNはcanonical quiet NaN `0x7fc00000`へ統一して比較します。対象は二値の組合せ回路であり、
例外フラグ、予約モード、X/Zを含むsimulation動作はHardFloatとの等価性の対象外です。
これは参照実装との等価性の証明で、IEEE 754規格そのものを独立に形式化した証明ではありません。

検証対象はcommit `313f67fb200236b4ee8489d6b1fc3d17a0eac395`の`fp32_fma.sv`です。
RTLのSHA-256は`7a7960ae91b3c5c44b3c6150ff2fae75f1e325f0527d1da33929bcf4709b2ff3`です。
証明はこのRTLに対するもので、後続のRTL変更には再検証が必要です。

元回路との対応を確認した乗算の補題と、後段の入力領域分割を組み合わせ、全入力を覆うことも確認しています。
この形式等価性検証の比較用コード・外部原本・詳細な手順と証拠は評価リポジトリで管理し、公開側には同梱しません。
HardFloatは検証時の比較対象であり、公開RTLの依存物ではありません。

## アルゴリズム

### 基本的な考え方

FMAでは、積の小さい桁が後の相殺で結果の上位に現れることがあります。
そのため24×24 bitの積を48 bitのまま保持し、指数を合わせた加数と広い整数回路で加減算します。
加算後に符号・大きさを確定し、正規化とsubnormalへの桁移動を含めて最後に一度だけ丸めます。
全体の処理は次のとおりです。

```text
入力の分類と指数・仮数の分離
  → 仮数の乗算と加数の桁合わせを並列に計算
  → 同じ桁位置で加減算
  → 先頭位置に合わせて正規化
  → 指定モードで一度だけ丸め、特殊値を選んで出力
```

区分間にレジスタはなく、全体が一つの組合せデータパスです。
まず、正規化数とsubnormalを同じ整数の格子で扱う方法を説明します。

指数fieldを`e`、fractionを`f`とし、`E=max(e,1)`、
`M={e != 0, f}`と置くと、有限入力の絶対値は`M * 2^(E-150)`です。
subnormalは隠れbitを0、指数を1として扱うため、入力側の正規化シフタは不要です。

積の基準指数を`Ep=Ea+Eb-127`とし、48 bitの積の下に3 bitを加えた整数を使います。
この整数の1 bitは`2^(Ep-176)`を表します。加数は同じ格子上の
`Mc * 2^(Ec-Ep+26)`へ桁合わせします。右に落ちるbitはstickyへまとめます。

整数和は77 bitの2の補数表現で、符号bitと下位76 bitからなります。

### 実装

以下では、上の処理を回路へ落とし込む際の幅削減と先行計算を、データの流れに沿って説明します。

#### 1. 加数シフトの制御を先行計算する

加数は`{Mc,52'b0}`を`d=Ea+Eb-Ec-101`だけ右へ動かします。
1／2／4／8 bitの段を早く開始できるよう、距離の下位4 bitだけを全幅の指数差と並列に計算します。
上位bitから下位bitへcarryは入らないため、次の式は近似ではなく同じ距離の厳密な変形です。

```text
d_low4 = (Ea[3:0] + Eb[3:0] + NOT4(Ec[3:0]) + 12) mod 16
```

subnormalの指数補正`E=max(e,1)`は共通です。16／32／64 bit段、負の距離でのbypass、
全桁が落ちる場合のsticky処理には元の指数差を使い、数値結果を変えません。

加数の左shiftが52 bitを超える場合、積は加数の隣接値間隔の半分より小さいので、
RNE／RMMでは加数をそのまま返せます。
方向指定の丸めでは、微小でも非zeroの積を無視せず、符号とモードに応じて
加数の隣接値へ1段進めます。加数が非zeroで積がzeroの場合は、全モードで加数をそのまま返します。
このbypass境界と、桁落ち・GRS・subnormal境界は個別に検証します。

#### 2. 上位carryの伝播条件を共有する

下位積和は乗算、加数の条件反転、carry-inを同じ式へ接続し、合成器による加算統合の余地を残します。
積は整数結果のbit 50以下にしかありません。そのため下位51 bitとcarryを52 bitの積和で計算し、
残る上位26 bitは加数側だけで先行処理できます。条件反転後の加数上位を`V`とすると、
`V+1`でbit `j`が反転する条件は、その下のbitがすべて1であることです。

```text
p[0] = 1
p[j] = AND(V[j-1:0])
upper_sum = V XOR (p AND {26{lower_carry}})
```

この`p`は下位積和を待たずに作れます。同じ条件を上位の先頭位置が変わるかの判定にも使い、
上位increment結果と位置補正用の判定を別々に計算しません。これは厳密な加算の分割であり、
積や加数の精度を落とす処理ではありません。

#### 3. 下位だけを検出し、上位の先頭位置は加数から求める

77 bitの整数和を`S`とすると、`S[75:0] XOR S[76:1]`の最高位の1は、
符号bitと異なる値が最初に現れる位置です。正値では`S`、負値では`|S|-1`の
最高位の1と一致するため、符号bitを76 bit全体へ配る反転を使わずに先頭位置を求められます。
負値の絶対値化に必要な`+1`は、後述のとおり最終丸めへ送ります。

ただし76 bit全域を検出する必要はありません。normal加数の先頭は桁合わせ前のbit 75にあるため、
上位に残っている間は整列距離`d`から分かります。下位carryによって先頭位置が変わる場合だけ、
加算なら距離を1減らし、減算なら1増やします。この判定にも上記の`p`を使います。
上位が減算で完全に消える場合は下位へ切り替えます。

下位内部は`S[49:0] XOR S[50:1]`の50 bitを、bit 0から49へ走査し、
1を見つけるたびに上端からの距離`75-i`を上書きします。最後に最高位の1の距離が残るため、
位置を求めてから減算する回路は記述しません。境界bit 50とcarry位置51は別に判定します。
下位に遷移がない場合の既定距離は75です。上位が有効なら補正済みの上位距離を選びます。

上位に残るsubnormal加数は隠れbitがないため、`d`を実際の先頭距離としては使いません。
この場合はsubnormalの固定格子を選び、左shift量を`Ep+25`とします。
それ以外もsubnormalのシフト上限を検出後に適用し、検出入力への上限maskは使いません。
データ用シフタには従来どおり生の77 bit整数和の下位76 bitを渡します。

#### 4. 正規化の窓を小さくする

出力に必要なのは24 bitの仮数とguard／round／stickyです。
先頭位置から左shift量を決め、各段で今後使わない下位桁をstickyへ集約すると、
全76 bitを最後まで動かす必要がなくなります。最終的に26 bitとstickyを残します。
subnormalでは左shift量を`Ep+25`以下に抑え、出力の最下位桁の重みを固定します。
`Ep<-25`のとき非zero加数はすでにbypassの対象であり、残る積は最小subnormalの半分未満です。
その場合は符号と丸め方向に応じてzeroか最小subnormalを返します。

#### 5. 絶対値化と丸めを一度の加算にまとめる

負の整数結果を`r=-m`とすると、bit反転だけで`~r=m-1`を得られます。
この値の先頭位置でshift量`s`を決め、生の`r`をzero-fillでshiftした後に反転すると、
保持する幅の範囲で`m*2^s-1`になります。fill部分も反転されるため、
強い相殺で下位桁が出力へ移る場合にも、絶対値化の`+1`を最後まで遅らせられます。

この値の保持仮数を`H`、guardを`G`、guardより下がすべて1である条件を`T`とすると、
負値経路で`H`へ加える増分は次のようにまとめられます。

| 丸めの選択 | 増分 |
|---|---|
| RNE | `G \|\| (H[0] && T)` |
| RMM | `G \|\| T` |
| 結果の絶対値を切り上げる方向 | `1` |
| 結果の絶対値を切り捨てる方向 | `G && T` |

方向指定の選択には、整数和の符号だけでなく積の符号も含めた最終結果の符号を使います。
`+1`が仮数へ繰り上がる場合は捨てた桁がすべて1なので、その補正後の値に端数は残りません。
したがって補正と丸めで仮数へ2回加算する必要はありません。
`T`は反転前の捨てたbitのORから求められ、別の広幅all-one回路も不要です。
厳密zero・特殊値・極小積の処理はこの通常経路から分離しています。

#### 6. 仮数の出力選択をまとめる

丸め後は、通常の仮数、加数bypassの仮数、最大有限値、NaNを排他的な条件で選び、ORでまとめます。
Infと厳密zeroでは、どの仮数も選ばず0にします。符号と指数の選択は仮数から分けています。

保持仮数24 bitへ加える増分は0か1なので、丸めcarryが立つのは全bitが1の仮数へ1を加える場合だけです。
このとき丸め結果の下位24 bitはすでに0となり、仮数出力は常に下位23 bitを使えます。
carryによる1 bit位置選択や仮数のzero強制は不要です。指数の繰り上がりとoverflowの判定には、
引き続きcarryを使います。normal経路では`rounded[24]`により指数を1増やし、
subnormal経路では`rounded[23]`により指数0か1を選び、最小normalへの繰り上がりも扱います。
丸めを省いたり、精度を落としたりする変更ではありません。

#### 主な演算資源

| ブロック | 主な幅 | 役割 |
|---|---|---|
| 仮数乗算 | 24×24 bit、積48 bit | binary32へ丸めず積を保持する |
| 加数整列 | 24 bit仮数から76 bit | 指数差に応じて右shiftし、落ちたbitをstickyへまとめる |
| 下位積和 | 52 bit（carry込み） | 積と加数の下位51 bitを加減算する |
| 上位補正 | 26 bit | 下位carryを先行計算した伝播条件へ反映し、下位51 bitと合わせて77 bitの和を作る |
| 先頭検出 | 下位50 bitの遷移、距離7 bit | 下位を走査し、上位は加数の整列情報と境界判定を使う |
| 正規化 | 76→57→41→33→29→27→26 bit | 保持窓を段階的に狭め、別途stickyを求める |
| 丸め | 保持仮数24 bit、結果25 bit | 絶対値化の補正とモード別増分を一度の加算へまとめる |
| 出力選択 | 仮数23 bit、符号・指数9 bit | 通常値、加数bypass、特殊値を選ぶ |

## 合成時の注意

合成トップは`FP32FMA`です。`fp32_fma.sv`だけを入力し、全体をclockなしの組合せ回路として扱います。
パイプラインレジスタやラッチは含みません。固定丸めモードで使う場合は`rounding_mode`を定数へ接続できます。

合成・gate検証は評価リポジトリで予備評価を行っています。電力、配置配線後の遅延、
実測遅延は未評価です。面積・遅延は評価環境と制約に依存するため、このREADMEでは規定しません。
