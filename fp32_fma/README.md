# FP32 FMA（試作）

binary32の三入力に対して`a * b + c`を計算する、clockなしの組合せ回路の試作です。
乗算結果をbinary32へ丸めずに加算し、最後に一度だけ、入力信号で指定したモードへ丸めます。
入出力subnormalを扱います。既存の初等関数unitとは別の実装です。

## 仕様

| 項目 | 内容 |
|---|---|
| トップ | `FP32FMA` |
| 入力・出力 | `a`、`b`、`c`、`result`各32 bit、IEEE 754 binary32。`rounding_mode`は3 bit |
| 演算 | `a * b + c`、乗算途中に丸めを入れない |
| 丸め | RNE・RTZ・RDN・RUP・RMMを実行時選択。各モードで正しく丸めた結果とのbit一致を目標とする |
| subnormal | 入力・出力とも対応、FTZなし |
| NaN | 入力NaN、`0 * Inf`、無限積と逆符号の無限加数は`0x7fc00000` |
| Inf・overflow | 無限入力は符号を保持したInf。有限値のoverflowはモードと符号によりInf／最大有限値を選択。相殺は丸め前に扱う |
| zero・underflow | 逆符号の厳密な相殺はRDNだけ`-0`、他は`+0`。同符号zero同士はその符号、非zeroのunderflowは結果の符号を保持 |
| 回路 | 純粋な組合せ回路。レジスタ・ラッチ・clock・reset・validなし |
| 未対応 | 例外フラグ、NaN payload伝播、乗算／加算以外のopcode |

### 丸めモード

| `rounding_mode` | モード | 丸め方向 | 有限値のoverflow時の出力 |
|---|---|---|---|
| `3'b000` | RNE | 最近接、同点は偶数 | 符号付きInf |
| `3'b001` | RTZ | zero方向 | 符号付き最大有限値 |
| `3'b010` | RDN | 負の無限大方向 | 正は最大有限値、負は`-Inf` |
| `3'b011` | RUP | 正の無限大方向 | 正は`+Inf`、負は負の最大有限値 |
| `3'b100` | RMM | 最近接、同点は絶対値が大きい側 | 符号付きInf |

`101`・`110`・`111`は未対応の符号化として`0x7fc00000`を返します。
CSR等から動的にモードを選ぶ機能は持たず、利用側で上記の値へ解決して入力します。
固定モードで使う場合もこの入力を定数へ接続できます。

`a`、`b`、`c`、`rounding_mode`の変化が組合せ遅延を経て`result`へ反映されます。
クロック境界での入力保持・出力取り込みが必要な場合は、利用側でレジスタを設けてください。
物理的な組合せ遅延は未測定であり、ゼロ遅延を意味しません。

## 基本的な考え方

FMAでは、積の小さい桁が後の相殺で結果の上位に現れることがあります。
そのため24×24 bitの積を48 bitのまま保持し、指数を合わせた加数と広い整数回路で加減算します。
加算後に符号・大きさを確定し、正規化とsubnormalへの桁移動を含めて最後に一度だけ丸めます。

指数fieldを`e`、fractionを`f`とし、`E=max(e,1)`、
`M={e != 0, f}`と置くと、有限入力の絶対値は`M * 2^(E-150)`です。
subnormalは隠れbitを0、指数を1として扱うため、入力側の正規化シフタは不要です。

積の基準指数を`Ep=Ea+Eb-127`とし、48 bitの積の下に3 bitを加えた整数を使います。
この整数の1 bitは`2^(Ep-176)`を表します。加数は同じ格子上の
`Mc * 2^(Ec-Ep+26)`へ桁合わせします。右に落ちるbitはstickyへまとめます。

| 区分 | 主な処理 | 内部幅 |
|---|---|---|
| 桁合わせ | 分類、指数差、加数の桁移動 | 24 bit仮数二個、76 bit加数 |
| 積和 | 24×24乗算と符号付き加減算 | 77 bitの整数結果 |
| 符号確定 | 符号を決め、負値の絶対値化に必要な`+1`を丸めへ送る | 76 bitの和の下位部分 |
| 正規化 | 先頭bit検出、normal／subnormalの桁移動 | 段階ごとに76→57→41→33→29→27→26 bit、別途sticky |
| 出力 | モード別丸め増分、指数carry、特殊値選択 | binary32結果 |

区分間にレジスタはありません。全体が一つの組合せデータパスです。

77 bitは76 bitの大きさと符号です。加数の左shiftが52 bitを超える場合、積は加数の
隣接値間隔の半分より小さいので、RNE／RMMでは加数をそのまま返せます。
方向指定の丸めでは、微小でも非zeroの積を無視せず、符号とモードに応じて
加数の隣接値へ1段進めます。加数が非zeroで積がzeroの場合は、全モードで加数をそのまま返します。
このbypass境界と、桁落ち・GRS・subnormal境界は個別に検証します。
積和は乗算、加数の条件反転、carry-inを同じ式へ接続し、合成器による加算統合の余地を残します。
面積・遅延は評価環境と制約に依存するため、このREADMEでは規定しません。

### 隣接bitで先頭位置を検出する

77 bitの整数和を`S`とすると、`S[75:0] XOR S[76:1]`の最高位の1は、
符号bitと異なる値が最初に現れる位置です。正値では`S`、負値では`|S|-1`の
最高位の1と一致するため、符号bitを76 bit全体へ配る反転を使わずに先頭位置を求められます。
負値の絶対値化に必要な`+1`は、後述のとおり最終丸めへ送ります。

このXORを使うのは先頭検出だけで、実際にシフトするデータは生の整数和です。
全bitが0または1なら先頭位置を0、上限適用前の左shift量を75とします。
subnormalのシフト上限は検出後に適用し、検出入力への上限maskは使いません。

### 正規化の窓を小さくする

出力に必要なのは24 bitの仮数とguard／round／stickyです。
先頭位置から左shift量を決め、各段で今後使わない下位桁をstickyへ集約すると、
全76 bitを最後まで動かす必要がなくなります。最終的に26 bitとstickyを残します。
subnormalでは左shift量を`Ep+25`以下に抑え、出力の最下位桁の重みを固定します。
`Ep<-25`のとき非zero加数はすでにbypassの対象であり、残る積は最小subnormalの半分未満です。
その場合は符号と丸め方向に応じてzeroか最小subnormalを返します。

### 絶対値化と丸めを一度の加算にまとめる

負の整数結果を`r=-m`とすると、bit反転だけで`~r=m-1`を得られます。
この値の先頭位置でshift量`s`を決め、生の`r`をzero-fillでshiftした後に反転すると、
保持する幅の範囲で`m*2^s-1`になります。fill部分も反転されるため、
強い相殺で下位桁が出力へ移る場合にも、絶対値化の`+1`を最後まで遅らせられます。

この値の保持仮数を`H`、guardを`G`、guardより下がすべて1である条件を`T`とすると、
負値経路で`H`へ加える増分は次のようにまとめられます。

| 丸めの選択 | 増分 |
|---|---|
| RNE | `G || (H[0] && T)` |
| RMM | `G || T` |
| 結果の絶対値を切り上げる方向 | `1` |
| 結果の絶対値を切り捨てる方向 | `G && T` |

方向指定の選択には、整数和の符号だけでなく積の符号も含めた最終結果の符号を使います。
`+1`が仮数へ繰り上がる場合は捨てた桁がすべて1なので、その補正後の値に端数は残りません。
したがって補正と丸めで仮数へ2回加算する必要はありません。
`T`は反転前の捨てたbitのORから求められ、別の広幅all-one回路も不要です。
厳密zero・特殊値・極小積の処理はこの通常経路から分離しています。

## 検証

```sh
make -C fp32_fma lint
make -C fp32_fma test
make -C fp32_fma stress
```

Verilator、C++17、MPFR／GMPを使います。MPFR 640 bitで積和を評価し、
RNE・RTZ・RDN・RUPはMPFRの対応モードでbinary32へ丸めた独立参照とbit比較します。
RMMはRNE結果を基準に、厳密な値が隣接するbinary32値の中点に一致する場合だけ
絶対値の大きい側を選びます。参照はRTLのGRS判定を共有しません。
640 bitは有限binary32積和の指数範囲を覆い、参照の積和を正確に保持する幅です。
NaNだけは仕様に従ってcanonical化します。

特殊値の直積、指数差・bypass境界、相殺、tie、丸めcarry、最小subnormal、最小normal、
overflowと相殺の組合せ、固定seed乱数を全5モードで検査します。
同じ三入力でモードだけを変える検査と、未対応符号化の検査も行います。
各入力の組合せ出力を直ちに照合します。
三入力全`2^96`組合せの全数検査や形式証明ではありません。`stress`は乱数を増やす追加標本検査です。
近似係数tableはないため、定数生成・定数照合は対象外です。

2026-09-26のVerilator 5.020／MPFR 4.2.1による検査では、全5モード合計で通常2,766,100件、
全有限指数field組合せの境界検査＋乱数500万組を含むstress 58,900,015件でbit不一致0でした。
1モードあたり通常553,220組、stress 11,780,003組の三入力を検査しています。
全有限指数と仮数内23位置で、相殺後の2の冪とその両隣を作る指向検査も含めています。
さらに各検査で未対応符号化52,728件が仕様どおりcanonical NaNとなり、lintもPASSしました。
乱数seedは`0xf32f0a01`、NaNはcanonical値で照合します。
「全有限指数field組合せ」は乗数二入力の指数0～254の組であり、全仮数・全加数の列挙ではありません。
合成・gate検証は評価リポジトリで予備評価を行っています。電力は未評価です。
